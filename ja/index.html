01 / アーキテクチャ

状況を把握できるエージェント運用。

作業を追うインターフェース。実行するためのランタイム。何が起きたかを理解する履歴。

01

プロジェクトと権限

案件ごとに固有の状況があります。ローカル版では、管理者、オペレーター、閲覧者の権限を持つプロジェクト単位で実行を管理できます。

02

API とキュー

リクエストはキューに入る前に検証されます。未完了タスクの制限で負荷を管理し、実行状態を把握できます。

03

ワーカーとコンテナー

ワーカーがリクエストを確保し、選択したバージョンを実行します。Docker のデモでは、ID で固定したイメージとリソース制限を使用します。

04

イベントと結果

入力、出力、記録されたイベントを確認できます。キューの待機時間や処理時間を確認し、実行を JSON でエクスポートできます。

現在のプロトタイプ
Python Docker

ローカルの Python 実行と Docker デモ、プロジェクト別履歴、初期アクセス制御。

次のステップ

顧客エージェントの統合、本番用ログイン、予算ポリシー。技術検証に応じてパイロットを開始します。

02 / 仕組み

エージェントを持ち込み、運用は Unitize に。

コードから追跡可能な運用までをシンプルにつなぎます。現在は自社のデモ用エージェントで初期機能を開発しています。

  1. 01

    バージョンを準備

    エージェントをパッケージ化し、入出力の契約を定義します。既存のコードとフレームワークを生かすことを目指しています。

  2. 02

    実行の条件を定義

    実行をプロジェクトに関連付け、操作できる人を選びます。新しいリクエストを受け付ける前に制限を設定します。

  3. 03

    実行して確認

    キュー、状態、イベントを確認します。開始前のリクエストをキャンセルし、処理時間を把握できます。

  4. 04

    理解して改善

    履歴とエクスポートした JSON を使って失敗を調査し、次のバージョンをチームと検討します。

03 / ソリューション

一つの基盤から、さまざまなサービスへ。

最初のデモから顧客向け運用まで、明確な段階で。

ソフトウェア開発会社

提供するエージェントの運用を整理できます。プロジェクトを分け、バージョンを固定し、各実行の履歴を確認できます。

01

インテグレーター

異なるツールで構築した成果物を、一つの運用基盤へ。パイロットごとに新しいダッシュボードを作る必要を減らします。

02

社内チーム

開発と運用で共有できる情報として、権限、キュー、処理の記録を提供します。

03

現段階では、任意コードの実行や本番環境の分離を保証していません。管理されたパイロットを通じて提供範囲を拡大します。
